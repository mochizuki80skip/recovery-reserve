0. 問題報告が来たら最初に確認すること

  1. 本番 URL で起きているか確認
    https://mochizuki-bn3q.vercel.app/
    プレビュー URL（途中にハイフンと記号が混ざるURL）は実験版なので、本番と挙動が違うことがあります。
  2. どの院・どの来院パターン・どのコース・何月何日何時かを聞き取る
    特定できると原因切り分けが速くなります。
  3. いつから起きているかを確認
    「今朝から」「予約後から」など。
  4. threease（スリーズプロ）側はどうか
    https://reservation.threease.com/192 を直接開き、同じ条件で同じ症状が出るかを比較。
    • threease でも同じ → threease の問題
    • threease は正常 → 当アプリの問題（開発側へ）

A. お客様側で起こりうる問題

お客様A-1. カレンダーで「?」と表示される

意味：「予約不可」ではなく「**未確認**」の状態。当アプリから threease への問い合わせが一時的に失敗した枠です。

対処：「?」マークをそのままタップすると、その枠だけキャッシュを通さず再取得します。成功すれば ○ または ─ に変わります。

再失敗：もう一度タップ → 何度でも再試行できます。3 回連続失敗するなら A-3 へ。

なぜ「?」になるか：誤って ○ で表示して「LINE 折り返しで取れません」を防ぐための安全側仕様です。

お客様A-2. アプリで ○ だったが LINE 確認で予約できなかった

原因：カレンダー表示から LINE 送信までの数分間に他の方が同じ枠を取った（最大 60 秒のキャッシュラグ）。

対処：お詫びの上、別枠を提案。第2・第3希望を入れてもらっておくと回避しやすい。

頻発する場合：キャッシュをさらに短くする調整が可能なので開発側に連絡。

お客様A-3. カレンダー全体が読み込めない

症状：「空き状況を取得できませんでした」と赤いエラーが表示。

対処順：

  1. 画面の「再読み込み」ボタンを押す
  2. 数十秒待ってもう一度
  3. ブラウザを完全に閉じて開き直す
  4. それでもダメならスタッフへ

スタッフの対応：

  1. threease の予約サイトを開いて threease 自体が落ちていないか確認
  2. Vercel のダッシュボード → Deployments が Ready か確認
  3. /admin の 📊 通信ログ で失敗率を確認
  4. threease ・ Vercel 両方正常なのに失敗率 50% 超 → 開発側へ連絡

お客様A-4. ロード中の進捗バーが途中で止まる

原因：一部の通信が極端に遅い／タイムアウト。

対処：30 秒経っても完了しなければ、画面を引っ張って更新（or ブラウザ更新）。

お客様A-5. LINE が開かない・文面が入っていない

  • LINE アプリが未インストール／古いバージョン
  • 当院公式 LINE を友だち追加していない

対処：クリップボードに文面はコピー済み。LINE で当院を検索→友だち追加→トーク欄を長押し→ペースト→送信、をご案内。

お客様A-6. 「3ヶ月以上来院なし」のコースが見当たらない

スタッフ確認：threease 管理画面 → メニュー一覧で「3ヶ月ご来院の無い方はこちら」「初診：オールインワン施術」が公開状態か。非公開だと当アプリにも表示されません。

お客様A-7. キャンペーン URL を開いたのに反応しない

  1. URL のコード（?promo= の後ろ）が正しいか
  2. 管理画面の「現在のキャンペーン」に該当コードが存在するか
  3. 存在するなら設定の見直し（A-8 / B-3 参照）

お客様A-8. キャンペーンが思った通りに動かない

→ B-3 を参照。

B. スタッフ側で起こりうる問題

スタッフB-1. 管理画面 (/admin) にログインできない

  1. パスワードの打ち間違い（半角全角・大小文字）
  2. ブラウザのキャッシュをクリア
  3. 何度も失敗するなら開発側に連絡（パスワードリセット可）
パスワードはチャットなどデジタルで共有しない。口頭・印刷物で管理。

スタッフB-2. 管理画面で「現在のキャンペーン」が読み込み中のまま

  1. F12 で開発者ツール → Console を確認
  2. Network タブで /api/admin/promos のレスポンスを確認
  3. 401 → 再ログイン
  4. 500 → Upstash Redis 接続切れの可能性。開発側へ連絡

スタッフB-3. 新規キャンペーンが期待通りに動かない

期待実際確認ポイント
カレンダーへ直行したい来院パターン選択画面が出る「URL を開いた時の挙動 → 指定済みの項目を自動入力」が ON か
価格を上書きしたい元の価格のまま種別が「価格を変更」+ 対象既存メニュー + 価格 が揃っているか
特定の院のみ両院で出る「対象院」が「両院」になっていないか
初回のみ表示2回目以降にも出る「対象来院」が「両方」になっていないか

キャンペーン一覧では「価格上書き／空き状況へ直行／新メニュー」のバッジと、対象院・来院・自動進行のタグが見えるので、まずはタグで設定意図を確認してください。

スタッフB-4. キャンペーン一覧から目的の URL が見つからない

  1. 種別タブ（価格上書き／空き状況へ直行／新メニュー）で絞る
  2. 検索ボックスでコード・名前・コース名を検索
  3. 院フィルタで三島／裾野に絞る

スタッフB-5. 通信ログの「成功率」が下がっている

意味：threease への問い合わせが頻繁に失敗。お客様画面で「?」が出やすくなっている状態。

考えられる原因：

  • threease 側の負荷増／一時不調
  • アクセス集中（チラシ配布直後など）
  • Vercel ↔ Upstash の通信不調

対処：30 分〜1 時間で自然回復するケースが多い。長引くなら開発側へ。

スタッフB-6. 院情報（住所・写真・LINE）が変わった／院が増えた

コード変更が必要なので、以下を開発側に伝達：

  • 新住所（〒+市町村+番地）
  • 院外観写真 JPG
  • LINE のベーシック ID（@xxxxx）
  • threease のプロバイダ ID（数字）

スタッフB-7. threease 側でコース名を変更したのに反映されない

当アプリは最長 10 分のコース一覧キャッシュ。10 分待っても変わらないなら開発側へ。

スタッフB-8. デプロイが反映されない

  1. Vercel → Deployments で最新コミットが Ready か確認
  2. Failed / Building が続く → Hobby プランの 1日 100 デプロイ上限の可能性
  3. Ready なのに見えない → Ctrl+Shift+R でハードリロード

スタッフB-9. ロゴ／院写真が表示されない

GitHub の reserve/img/ 配下に画像が存在するか、ファイル名が clinic-mishima.jpg / clinic-susono.jpg / reserve/logo.jpg になっているか確認。

C. 開発側へエスカレーションするときに伝える情報

  1. 発生時刻（できれば分単位）
  2. 対象（院・来院パターン・コース・日時）
  3. 症状のスクリーンショット
  4. ブラウザの開発者ツール → Console タブの赤いエラー文字
  5. 直近の設定変更（キャンペーン追加、threease 側のメニュー変更など）

D. 定期チェック（推奨）

頻度内容
毎朝管理画面トップで通信ログの成功率を確認（99% 以上なら正常）
週1回公式 URL を実際に操作し、予約フローが通せるか確認
月1回キャンペーン一覧を見て、不要なキャンペーンを削除
設定変更時本番 URL で実際にテストして期待通りに動くか確認
