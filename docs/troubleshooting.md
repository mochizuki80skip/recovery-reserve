# リカバリー鍼灸院 予約サイト — 運用トラブルシューティング

最終更新: 2026-05

このアプリ（`mochizuki-bn3q.vercel.app`）の問題発生時の対処フローです。
症状ごとに「原因の見立て → 最初に試すこと → それでもダメな時」の順で記載しています。

---

## 0. 共通：状況確認のスタート地点

問題報告が来たら、まず以下を確認してください。

1. **本番 URL** で起きているか？  
   `https://mochizuki-bn3q.vercel.app/` （プレビュー URL は一時的な実験版）
2. **どの院・どの来院パターン・どのコース・何月何日何時** か？  
   日時を特定できると原因切り分けが速い
3. **発生したのはいつか？**  
   「今朝から」「特定の予約後から」など、時間軸が分かるとログと照合できる
4. **threease 側はどうか？**  
   ブラウザで `https://reservation.threease.com/192` を開き、同じ条件で同じ症状が出るか確認
   - threease 側でも同じ → threease の問題（待つか問い合わせ）
   - threease は正常 → 当アプリの問題

---

## A. お客様側で起こりうる問題

### A-1. カレンダーで枠が「?」と表示される

| | |
|---|---|
| **症状** | カレンダーの一部のマス目に `?` が出ている |
| **意味** | 当アプリから threease への問い合わせが失敗した枠（成功か失敗か確定していない状態） |
| **対処** | **「?」マークをタップする**と、その枠だけキャッシュを通さず再取得します。成功すれば ○ または ─ に変わります |
| **再失敗の場合** | もう一度タップすれば再々取得。3 回連続失敗するなら → A-3 へ |

> 仕様：「?」は「予約不可」ではなく「未確認」を意味します。誤って ○ で表示して LINE で「すみません取れません」になるのを防ぐ安全側の挙動です。

---

### A-2. アプリで ○ だったのに LINE 確認で予約できなかった

| | |
|---|---|
| **症状** | カレンダーで ○ だった時刻が、LINE 折返しで「すみません取れません」 |
| **原因** | カレンダー表示後の数分間に、他のお客様が同じ枠を取った（最大 60 秒のキャッシュラグ）|
| **対処** | お客様にはお詫びの上、別枠を提案。第2・第3希望を入れてもらっておくと回避しやすい |
| **頻発する場合** | 院長判断でキャッシュをさらに短く（60 秒 → 30 秒）してもらう。私（開発側）に連絡 |

---

### A-3. カレンダー全体が読み込めない

| | |
|---|---|
| **症状** | 「空き状況を取得できませんでした」と赤いエラー |
| **対処順** | ① **「再読み込み」ボタン**を押す<br>② 数十秒待ってもう一度<br>③ ブラウザを完全に閉じて再度開く<br>④ それでもダメなら staff に連絡 |
| **staff の対応** | (1) threease の予約サイトを開いて threease 自体が落ちていないか確認<br>(2) Vercel のダッシュボードを開き「Deployments」が Ready か確認<br>(3) `https://mochizuki-bn3q.vercel.app/admin` の **📊 通信ログ** で失敗率を確認<br>(4) threease が動いている／Vercel も動いているのに失敗率 50% 超 → 私（開発側）に連絡 |

---

### A-4. ロード中の進捗バーが途中で止まる

| | |
|---|---|
| **症状** | 「空き状況を取得中… 47%」のまま 30 秒以上動かない |
| **原因** | 1〜2 枠分の通信が極端に遅い／タイムアウト |
| **対処** | 30 秒待っても表示されない場合、ブラウザの更新ボタン（or 引っ張って更新）でリトライ |
| **staff の対応** | 通信ログを確認。連続でこの症状が出るならキャッシュをクリア（私に連絡） |

---

### A-5. LINE が開かない・文面が入っていない

| | |
|---|---|
| **症状** | 「コピーして公式LINEを開く」を押しても LINE アプリが起動しない、または文面欄が空 |
| **原因 (a)** | LINE アプリが未インストール／古いバージョン |
| **原因 (b)** | スマホの LINE で公式アカウントを未友だち追加 |
| **対処** | クリップボードには文面がコピーされているので、お客様に「**LINE で当院を検索して友だち追加 → ペーストして送信**」をご案内 |
| **追加の安全策** | お客様にはご来院チラシに友だち追加の QR コードを掲載しておく |

---

### A-6. 「3ヶ月以上来院なし」のコースが見当たらない

| | |
|---|---|
| **症状** | STEP1 で「3ヶ月以上来院なし」を選んだのにコースが出ない |
| **対処** | しばらく経ってもう一度。それでもダメなら、threease 側のメニュー設定で「3ヶ月ご来院の無い方はこちら」が公開状態か確認 |
| **staff の対応** | threease 管理画面 → メニュー一覧で当該コースが「公開」になっているか確認。非公開だと当アプリにも出ません |

---

### A-7. キャンペーン URL (`?promo=xxx`) を開いたのに反応しない

| | |
|---|---|
| **症状** | チラシ／LINE 配信などで配ったキャンペーン URL を開いても何も起きない、または通常画面と同じ |
| **対処** | (1) URL のコードが正しいか確認（`?promo=` の後の文字列）<br>(2) 管理画面 → 「現在のキャンペーン」で該当 URL コードが**存在するか**確認<br>(3) コードはあるが反応しない場合 → 設定の見直し（A-8 参照）|

---

### A-8. キャンペーン設定が思った通りに動かない

詳しくは **B-3** を参照。

## B. スタッフ側で起こりうる問題

### B-1. 管理画面 (`/admin`) にログインできない

| | |
|---|---|
| **症状** | パスワードを入れてもエラー |
| **対処** | (1) パスワードに半角全角・大文字小文字の打ち間違いが無いか<br>(2) ブラウザのキャッシュをクリア<br>(3) 何度も失敗するなら開発側に連絡（パスワードリセット可能） |
| **重要** | パスワードは **特定のスタッフのみ知っている** ことが原則。共有はチャットなどではなく口頭・印刷物で |

---

### B-2. 管理画面で「現在のキャンペーン」が読み込み中のまま

| | |
|---|---|
| **症状** | リスト部分がいつまでも「読み込み中…」表示 |
| **対処** | (1) ブラウザのコンソール（F12）でエラーを確認<br>(2) `/api/admin/promos` のレスポンスをネットワークタブで確認<br>(3) `401 Unauthorized` → 再ログイン<br>(4) `500` → Upstash Redis の接続が切れている可能性。私に連絡 |

---

### B-3. 新しく作ったキャンペーンが期待通りに動かない

| 期待した動作 | 実際 | 確認ポイント |
|---|---|---|
| カレンダーに直行したい | 来院パターンの選択画面が出る | 「**URL を開いた時の挙動 → 指定済みの項目を自動入力**」が ON か |
| 価格を上書きしたい | 元の価格のまま | 種別が「**既存メニューの価格を変更**」+ 対象既存メニュー指定 + 価格が入力済みか |
| 特定の院のみで使いたい | 両院で出る | 「対象院」が「両院」になっていないか |
| 初回のみ表示 | 2回目以降にも出る | 「対象来院」が「両方」になっていないか |

**チェックの順番**：
1. 管理画面 →「現在のキャンペーン」で該当 URL の **設定タグ** を見る（タグで対象院・対象来院・自動進行等が一目で確認できる）
2. タグの内容を意図と照合
3. 違っていれば「編集」で修正

---

### B-4. キャンペーン一覧から目的の URL が見つからない

| | |
|---|---|
| **症状** | たくさん作ったキャンペーンの中から探したい URL が分からない |
| **対処** | 管理画面 →「現在のキャンペーン」上部の<br>① **種別タブ**（価格上書き／空き状況へ直行／新メニュー）で絞る<br>② **検索ボックス**にコード・名前・コース名を入力<br>③ **院フィルタ**で三島／裾野に絞る |

---

### B-5. 通信ログの「成功率」が下がっている

| | |
|---|---|
| **症状** | 管理画面トップ「📊 通信ログ」で成功率が 90% 台前半 〜 80% 台 |
| **意味** | threease への問い合わせが頻繁に失敗。お客様画面で「?」が出やすくなっている |
| **原因の見立て** | (a) threease 側の負荷増／一時的な不調<br>(b) アクセス集中（チラシ配布直後など）<br>(c) Vercel↔Upstash の通信不調 |
| **対処** | (1) しばらく様子を見る（30 分〜1 時間で回復することが多い）<br>(2) 回復しない場合 → 私に連絡 |
| **緊急時の応急処置** | 私側で「キャッシュ TTL を 60 秒 → 300 秒」に変更すれば threease への呼び出しが激減し、復帰しやすくなる |

---

### B-6. 院の住所・電話番号が変わった／院が増えた

| | |
|---|---|
| **対処** | コード変更が必要。私に以下を伝えてください：<br>・新住所（〒+市町村+番地）<br>・院の外観写真 (JPG)<br>・LINE のベーシック ID (@xxxxx)<br>・threease のプロバイダ ID（数字）|

---

### B-7. メニュー（コース）名や時間が threease で変わった

| | |
|---|---|
| **症状** | threease 側でコース名を変更したのに当アプリで反映されていない |
| **原因** | コース一覧の Vercel エッジキャッシュ（最長 10 分） |
| **対処** | 最大 10 分待つ。それでも変わらないなら開発側に連絡 |

---

### B-8. デプロイが動かない／反映されない

| | |
|---|---|
| **症状** | コード変更後、本番に変化が見えない |
| **対処** | (1) Vercel ダッシュボード →「Deployments」で最新コミットが Ready か確認<br>(2) Failed/Building が長時間続く → Vercel の利用上限（Hobby は 1日 100 デプロイ）に達した可能性<br>(3) Ready なのに見えない → ブラウザを **Ctrl+Shift+R** でハードリロード |

---

### B-9. ロゴ／院写真が表示されない

| | |
|---|---|
| **対処** | GitHub の `reserve/img/` 配下に画像があるか確認。<br>ファイル名が `clinic-mishima.jpg` / `clinic-susono.jpg` / `reserve/logo.jpg` であること |

## C. 連絡先 / エスカレーション

問題が解決しない場合は、以下を添えて開発側に連絡してください：

1. **発生時刻**（できれば分単位）
2. **対象**（院・来院・コース・日時）
3. **症状のスクショ**
4. **ブラウザの開発者ツールのコンソール内容**（F12 → Console タブ、赤いエラー）
5. **直近で何か設定変更をしたか**（キャンペーン追加、threease 側のメニュー変更など）

---

## D. 定期チェック（推奨）

| 頻度 | 内容 |
|---|---|
| 毎朝 | 管理画面トップで通信ログの成功率を確認（99% 以上なら正常） |
| 週1回 | 公式 URL を実際に操作してみて、自分が予約できるか確認 |
| 月1回 | キャンペーン一覧を見て、不要なキャンペーンを削除 |
| 設定変更時 | 必ず本番 URL でテストして期待通りに動くか確認 |

## E. 用語集

| 用語 | 意味 |
|---|---|
| threease（スリーズプロ） | 当院が使っている予約管理 SaaS。当アプリは threease のデータを表示しているだけで、実予約は threease に入る |
| 公式LINE | お客様が予約希望を送る LINE 公式アカウント（院ごとに別） |
| ベーシック ID | LINE 公式アカウントの `@xxx` 形式の ID |
| プロバイダ ID | threease 内での院 ID（三島=192, 裾野=193）|
| Vercel | このアプリのホスティング先 |
| Upstash Redis | キャンペーン設定の保存先（KV ストア） |
| キャッシュ | 過去の取得結果を一定時間使い回す仕組み。早いが古い情報を返すこともある |
| エッジ | Vercel が地理的に分散しているサーバー群。ユーザーに近いサーバーから返す |
